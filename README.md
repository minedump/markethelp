# MarketHelp — новый сайт

Статический сайт на Next.js, который собирается из UI-кита.

```
web/        Сайт: Next.js 15, Tailwind, статический экспорт в out/
```

Рядом на диске, но вне репозитория (публичный гит — не место для
внутренних материалов и чужого прайса):

```
kit/        UI-кит: единственный источник оформления. Правится только он.
site/       Макет сайта одним файлом — то, из чего перенесён web/
pricelist/  Прайс-лист и его PDF
card/       Карточка предприятия и её PDF
photos/     Съёмка склада → картинки сайта: кадрирование и обработка
tilda/      Блок контактов с картой для нынешнего сайта на Tilda
sources/    ТЗ, тексты, аудит дизайна, переписка
```

Кит в репозиторий не входит, но сайт по-прежнему собран из него и
правила кита на него распространяются. Витрина кита живёт отдельной
страницей, и она же — рабочий экземпляр: правится она, а `/kit/`
на сайте повторяет её React-компонентами.

## Правило

Ни одна страница не описывает оформление сама: кнопки, поля, таблицы,
заголовки, плитки — всё берётся из кита. Если элемента в ките нет —
он сперва появляется там, с пояснением зачем, и только потом на странице.

Кит перенесён в компоненты: `web/components/ui/` — те же классы, те же
пояснения. Слой стилей кита целиком лежит в `web/app/globals.css`;
оформление самого сайта (шапка, логотип, бегущая строка) — отдельным
блоком в конце того же файла, помеченным.

Содержание и тексты не живут в разметке: они в `web/content/`.
Неразрывные пробелы расставляются сами — `web/lib/typo.ts`.

## Сборка

```
cd web
npm ci
npm run dev        # localhost:3000
npm run build      # статический экспорт в web/out
```

Боевая сборка — с адресом сайта и включённым счётчиком:

```
NEXT_PUBLIC_SITE_URL=https://markethelp.ru NEXT_PUBLIC_METRIKA=1 npm run build
```

Переменные:

| Переменная               | Зачем                                                        |
| ------------------------ | ------------------------------------------------------------ |
| `NEXT_PUBLIC_SITE_URL`   | адрес для canonical, карты сайта и картинки ссылок            |
| `NEXT_PUBLIC_METRIKA=1`  | включает Яндекс Метрику и открывает сайт в `robots.txt`       |

Без переменных сборка считается тестовой: счётчика нет, а `robots.txt`
закрывает сайт целиком — чтобы поисковик не проиндексировал тестовый
домен и не склеил его с боевым.

## Проверки

```
cd web
npm run build
npm run check      # внутренние ссылки и якоря: ни одной битой
npm run kit-lint   # страницы не переопределяют кит
npx tsc --noEmit   # типы
```

`kit-lint` сверяет собранные страницы с китом и поэтому работает
только там, где кит лежит рядом с репозиторием. Без него проверка
не падает, а пишет, чего не хватает, и пропускается — сборке на
сервере ронять себя не за что.

Отдельно по киту, из корня, тоже только с китом на диске:

```
node kit/check.js        # все фирменные цвета в классах существуют
node kit/tip-test.js     # геометрия подсказки, 12 случаев
```

## Прайс-лист в PDF

Файл лежит в сборке — `web/public/pricelist/`, на него ведут кнопки
«Скачать прайс в PDF» на страницах тарифов и услуг. Адрес задан один
раз, в `PRICELIST` (`web/content/pages.ts`).

Сам он не пересобирается. Цены на странице тарифов идут из
`web/content/prices.ts`, а PDF — из `pricelist/prices.py`; это два
отдельных файла с одними и теми же числами, и при правке цен нужно
пройти обе стороны, иначе сайт и скачанный прайс разойдутся:

```
# 1. поправить цены в обоих файлах
#    pricelist/prices.py   — для PDF
#    web/content/prices.ts — для сайта
# 2. пересобрать PDF и положить его в сборку
python pricelist/build.py && python pricelist/make-pdf.py
cp "pricelist/MarketHelp — прайс-лист 2026.pdf" web/public/pricelist/
```

## Фотографии склада

Снимки в `web/public/assets/` — съёмка склада от 8 октября 2026.
Исходники и сборщик лежат в `photos/` рядом с репозиторием: в нём
карта «место на сайте → кадр», кадрирование под 4:3 и обработка.

```
python photos/build.py series     # обработка по умолчанию
python photos/build.py raw        # без обработки, цвет как снят
python photos/build.py cool       # холодные тени, ближе к палитре
```

Обработка приводит кадры к одной серии: общий баланс белого, поднятые
тени, приглушённый оранжевый. Без неё шесть снимков выглядят папкой
«разное», а тёплый складской свет спорит с синим сайта.

Фотографий нет для четырёх ниш на «О компании» (одежда, техника,
хрупкое, крупногабарит) и для Китая — там по-прежнему рисованные
заглушки: в съёмке всюду картон, а плитки нужны, чтобы ниши
отличались друг от друга.

## Карточка предприятия в PDF

Файл лежит в сборке — `web/public/requisites/`, на него ведёт кнопка
«Скачать карточку предприятия» на странице реквизитов. Адрес задан
один раз, в `REQUISITES_FILE` (`web/content/documents.ts`).

Собирается сборщиком `card/` рядом с репозиторием — один лист A4:
логотип с контактами сверху, под ними таблица. Реквизиты он читает
прямо из `web/content/contacts.ts`, поэтому двух списков, как у цен,
здесь нет: поправить нужно только содержание сайта и пересобрать.

```
# после правки REQUISITES в web/content/contacts.ts
python card/build.py && python card/make-pdf.py
```

`make-pdf.py` сам кладёт готовый файл в `web/public/requisites/`.
Печатает Chrome без окна, и ему нужна сеть: стили и шрифт идут с CDN.

## Цели Метрики

Имена целей — в `GOALS` (`web/content/site.ts`), отправка — через
`goal()` (`web/lib/goal.ts`): если счётчика на странице нет, вызов
молча пропускается.

| Цель            | Когда срабатывает                                   |
| --------------- | --------------------------------------------------- |
| `phone-reveal`  | нажали на замаскированный номер в шапке или в меню   |
| `phone-call`    | нажали на сам номер — ссылку `tel:` где угодно       |

Нажатия по `tel:` ловит один слушатель на страницу —
`components/site/PhoneGoal.tsx`; вешать обработчик на каждую ссылку
значило бы делать клиентским каждый блок, где она встретилась.

**В Метрике цели нужно завести вручную** — как JS-цели с этими же
идентификаторами, иначе события приходят в никуда.

Заявку целью не заводим: «Заявка принята» — отдельный адрес, и цель
на посещение страницы надёжнее события.

## Перенос со старого сайта

Записи блога перенесены с Tilda в `web/content/blog.ts`. Карта
редиректов со старых адресов и порядок их установки — в
[REDIRECTS.md](REDIRECTS.md); ставятся на боевом домене.

## Что ещё не включено

- Заявка никуда не отправляется: приёмник появится вместе
  с `app.markethelp.ru`. Места отмечены в коде — `RequestModal.tsx`
  и `ContactForm.tsx`.
- Кнопка личного кабинета скрыта: `APP.ready` в `web/content/site.ts`.
- В блоге две записи — обе перенесены со старого сайта. Темы, под
  которые верстался макет, удалены: тексты и цифры в них были придуманы
  для показа вёрстки. Новая запись добавляется в `POSTS` и `ARTICLES`
  (`web/content/blog.ts`).
- В текстах остались пометки «уточнить» там, где ждём цифры от склада.
